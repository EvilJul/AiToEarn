# 企业 AI 内容营销与智能接待：二次开发需求归档

- 版本：V0.1
- 归档日期：2026-10-17
- 状态：需求基线草案，待客户确认及技术验证
- 代码基础：`EvilJul/AiToEarn`，上游 `yikart/AiToEarn`
- 来源：本次沟通中的客户口述、需求 Q&A 与项目能力初步对照

本文用于保存二次开发意图，不代表功能已实现或已完成报价。文中的 P0/P1/P2 是产品建议，尚未获得客户范围确认。本次归档不修改现有业务代码。

## 1. 客户目标

帮助企业持续生产适合自身业务及目标平台的精美内容，结合时下热点、地域及行业关键词获得目标客户曝光。客户发起咨询后，由机器人及时承接、识别意向并提醒销售人工接管，减少漏接与漏跟进。

客户认为核心难点是切中当下热点和行业需求、提升相关曝光；自动发布与机器人回复是基础能力。

客户口述预算约为每月 1,000～2,000 元，倾向长期订阅。计费单位、服务内容、外部服务费用及广告预算尚未明确，不能视为已确认报价。

## 2. 目标业务流程

企业资料建档 → 获取热点 → 匹配行业与地域 → 推荐选题与关键词 → AI 生成图文 → 企业审核 → 排期发布 → 收集内容表现与咨询 → 机器人接待 → 识别意向 → 提醒销售 → 人工接管 → 跟进记录与效果复盘。

客户提及小红书、微博等平台，并以无锡为地域示例；首期实际平台、城市与行业仍需确认。

## 3. 已有能力与复用边界

以下为此前根据上游 README 得到的初步结论，未进行源码逐项审计或端到端实测。不能据此承诺所有能力都已包含在开源版或可独立自部署运行。

- 内容创作：文档列有图文、图片、视频及批量草稿生成，可作为创作基础；企业知识约束与品牌模板需要验证和补充。
- 多平台发布：文档列有小红书等平台分发及日历排期；微博不在此前核对的支持清单内，须单独验证。
- 评论互动：文档列有插件评论回复及购买意向信号识别；不能等同于完整的平台私信客服。
- 热点运营：文档列有品牌监测与热点参与描述，但未确认地域、行业、企业匹配及效果反馈的完整实现。
- 销售协同：尚未确认有销售分配、通知升级、人工接管和跟进闭环；列为待核实及拟开发范围，不能直接认定代码完全没有相关功能。

## 4. 拟开发需求

### R01 企业知识与品牌资料（P0）

维护企业行业、服务区域、产品、目标客户、卖点、价格口径、真实案例、常见问题、品牌语气和禁用表述。支持资料审核、更新与版本追踪，供创作和接待共同使用。

验收要点：内容和回答可关联企业资料；不允许模型自行补写价格、案例或效果保证。不同企业的资料和访问权限隔离。

### R02 地域与行业热点选题（P0，核心差异点）

接入经确认可用的数据源，按平台、地域、行业与企业产品筛选热点，输出候选选题、关键词、推荐理由、来源、采集时间和有效期。支持人工采纳、拒绝和反馈。

验收要点：能解释热点与目标业务的联系；过期或无关热点可过滤；数据源不可用时有状态提示和替代选题。数据权限、更新频次和成本须先完成验证。

### R03 企业图文生成与平台排版（P0）

基于企业资料与选题生成标题、正文、配图或配图建议、话题标签和咨询引导。按平台适配篇幅、段落、图片比例及品牌模板，支持预览、编辑、退回与审核。

验收要点：审核前不能进入正式发布；企业事实和案例有依据；平台版本可分别确认。客户口述“实事”究竟指时事、实用还是事实准确，需确认。

### R04 发布与任务追踪（P0，优先复用）

复用已验证的账号授权、排期和发布能力，补充审核状态、发布记录、失败原因、重试和重复发布保护。保留平台链接或可核验结果。

验收要点：明确区分提交成功、平台审核中、发布成功与失败；超时重试不造成重复发布。按平台、账号类型和内容形式验证能力，不能将某个平台可用推及全部平台。

### R05 企业知识问答与咨询承接（P0）

在经验证可接入的咨询渠道中，提供基于企业资料的多轮问答和需求收集。问题超出资料范围、用户要求人工或涉及重要承诺时进入人工流程。

验收要点：评论与私信渠道分别验收；对话有上下文和处理状态；不得编造报价和服务承诺。首次响应时限待客户确认。

客户希望争取 3～5 分钟或更长时间供销售上线。产品目标应为及时解决问题、识别需求和顺利交接；对话时长仅作观察指标，不通过拖延或重复提问强行延长。

### R06 意向识别与销售提醒（P0）

按询价、预约、购买意愿、用户主动留资和人工请求等规则识别线索。向对应销售或管理员发送来源、需求摘要、意向依据、最近对话和接管入口。

验收要点：命中规则后通知正确人员；通知结果可追踪，重复事件有去重。通知渠道、销售分配与响应时限待确认。

### R07 人工接管与跟进记录（P0）

维护机器人接待、等待人工、人工接管、已结束状态。人工确认接管后暂停自动回复，避免抢答。无人响应时升级提醒，支持回访任务和处理记录。

验收要点：接管状态一致且切换可追踪；销售可查看对话并续接；未处理咨询可查询。超时阈值、备用人员和机器人恢复规则待确认。

### R08 内容与线索效果复盘（P1）

记录选题、关键词、发布内容、可取得的曝光和互动数据，以及有效咨询、留资、预约和成交反馈。观察哪些主题带来目标客户，辅助下一轮选题。

验收要点：标明来源、口径、更新时间及缺失数据；能区分内容关联与已证实归因；不因无法获取数据而显示为零。成交需客户回传或接入 CRM。

### R09 关键词及曝光持续优化（P1）

支持关键词分组、常规选题与热点选题对照、效果反馈和策略调整。在权限与数据条件允许时观察指定关键词下的搜索可见度。

验收要点：排名观察约定地域、账号、时间和采样方式；不承诺固定排名、自然推荐位置或固定线索量。付费推广另行确认。

### R10 企业服务与订阅管理（P2，商业化前确认）

如面向多家企业收费，需核实并补充企业隔离、角色权限、账号与素材配额、模型用量及费用记录、套餐和订阅管理。优先复用已有相关模块。

验收要点：企业之间不能越权访问内容和咨询；用量可归属企业并可核对；套餐边界及超量处理明确。

## 5. 建议实施阶段

1. **能力验证**：审计相关源码并实测创作、目标平台发布、消息入口及外部服务依赖，确认热点数据源。形成可复用、需改造及新增项清单。
2. **单场景试点**：选择一个行业、一个地域、一个主要发布平台和一个可接入咨询渠道，完成 R01～R07 的最小完整流程。
3. **试运营优化**：补充 R08～R09，依据曝光、有效咨询和销售接管结果优化选题与接待。
4. **规模化服务**：按验证结果增加平台、行业及 R10，确定套餐、运营成本和服务标准。

优先级不代表上线顺序。平台消息权限和热点数据源属于前置依赖；未验证前不承诺开发周期。

## 6. 评估指标与验收原则

- 内容：审核通过率、发布成功率、失败原因与人工处理时间。
- 曝光：可取得的曝光、阅读、互动及关键词搜索表现。
- 接待：首次响应时长、未处理咨询、销售响应时间和接管成功率。
- 获客：有效咨询、留资、预约和可核验成交。
- 成本：单篇内容成本、有效线索成本及企业月度服务成本。

指标目标值、基线、试运营周期和“有效咨询”定义由双方另行确认。软件功能验收与获客效果评估分开；发布数量和聊天时长不能单独代表业务成功。

“不放走任何客户”落实为已接入渠道内尽量不漏接、不漏提醒、不漏记录，不解释为保证所有访客咨询、留资或成交。

## 7. 暂不默认包含的范围

全平台全内容类型接入、视频批量生产、广告代投、批量主动私信、复杂 CRM 定制、全天候人工运营、固定排名或固定成交保证。上述事项如需加入，应单独评估范围、权限、费用与验收。

## 8. 外部依赖与实施约束

- 平台发布、消息、数据读取分别核实接口权限、账号资质及插件或中继依赖。
- 数据获取方式、使用授权、调用费用和数据质量在接入前确认。
- AI、图片、存储、中继和消息通知的成本计入单位经济模型。
- 使用中继等服务时严格区分中国版 `*.aitoearn.cn` 与国际版 `*.aitoearn.ai`，凭据与所属环境匹配。
- 企业资料及咨询记录明确访问权限、保存期限、导出与删除规则。
- MIT 代码授权不等于平台权限或第三方云服务免费。

## 9. 待客户确认

1. 首期行业、目标客户和真实服务区域；无锡是否为实际范围。
2. 首期发布及咨询平台、账号数量、账号资质，微博是否必须支持。
3. 内容频次、图文或视频范围、品牌模板、素材来源和审核负责人。
4. 热点更新时效、数据采购预算及“排名”的具体含义。
5. 咨询入口、企业问答范围、重要客户与有效线索定义。
6. 销售分配、提醒渠道、响应时限、非工作时间及升级规则。
7. 是否对接现有 CRM，是否能回传预约、成交及收入数据。
8. 每月 1,000～2,000 元的计费单位、包含项目、超量费用和投放预算。
9. 试运营周期、效果评估口径、数据保存和隐私管理要求。

## 10. 归档结论

拟以 AiToEarn 的创作与发布能力为基础，二次开发重点放在企业知识约束、地域与行业热点匹配、咨询接待及销售协同。下一步先完成能力验证和客户范围确认，再拆分技术方案与开发任务。
